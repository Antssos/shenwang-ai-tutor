# 申望 AI 助教前端接入说明

## 当前环境

Dify 社区版运行在团队云服务器中，模型推理全部调用外部模型 API。Dify 管理后台目前只通过 SSH 隧道访问，尚未配置正式公网域名和 HTTPS。

前端不应直接访问 Dify 管理后台，也不能在浏览器、小程序或前端代码中保存 Dify API Key。

推荐链路：

```text
Web / 微信小程序
→ 团队后端代理
→ Dify 应用 API
→ 外部模型 API
```

## 开始开发前需要提供

后端或 Dify 负责人需要向前端确认：

1. 测试环境代理地址。
2. 正式环境代理地址。
3. 应用类型：Chatflow、Workflow 或普通聊天应用。
4. 前端业务接口及其认证方式。
5. 是否使用 SSE 流式响应。
6. 是否支持文件或图片上传。
7. 会话历史是否由前端保存。
8. 超时、限流和错误码规则。

Dify API Key 只配置在后端代理的环境变量中，不提供给前端。

## 建议的前端业务接口

### 发送聊天消息

```http
POST /api/chat
Content-Type: application/json
```

请求示例：

```json
{
  "message": "五年级数学这道题怎么做？",
  "conversation_id": "",
  "user_id": "anonymous-user-id"
}
```

字段说明：

- `message`：用户输入，必填。
- `conversation_id`：首次为空，后续使用服务端返回值继续会话。
- `user_id`：稳定的匿名用户标识，不使用姓名、手机号等个人信息。

建议使用 SSE 流式响应。前端至少处理：

- 文本增量事件；
- 消息完成事件；
- 错误事件；
- `conversation_id`；
- `message_id`；
- 网络中断和用户主动停止。

### 停止生成

```http
POST /api/chat/{task_id}/stop
```

用于用户主动停止正在生成的回答。是否在第一版实现，可根据进度决定。

### 文件上传

文件上传暂不作为第一版默认能力。后续启用时必须明确：

- 文件类型；
- 文件大小；
- MIME 和实际内容校验；
- 上传进度；
- 删除和保存期限；
- 图片及儿童个人信息处理规则。

## 前端必须实现的状态

聊天界面至少需要：

- 初始欢迎状态；
- 用户输入状态；
- 正在连接状态；
- 流式生成状态；
- 用户停止状态；
- 请求超时状态；
- 服务不可用状态；
- 空答案或知识库无答案状态；
- 高风险内容固定引导状态。

## 安全要求

- 不在前端代码中写入 Dify API Key、模型 API Key 或服务器凭据。
- 不允许浏览器直接调用带密钥的 Dify API。
- 不使用客户端 UUID 作为唯一安全措施。
- 后端必须实施限流、输入长度限制和日志脱敏。
- 前端不得要求儿童输入姓名、住址、电话或照片。
- 高风险问题由 Dify 固定安全分支处理，前端不得改写成普通聊天回复。
- 正式环境必须使用 HTTPS。

## 联调顺序

1. 使用固定模拟数据完成聊天界面。
2. 对接非流式测试接口。
3. 对接 SSE 流式响应。
4. 保存并复用 `conversation_id`。
5. 测试刷新页面、网络中断和重复提交。
6. 测试知识库命中、无答案拒答和安全分流。
7. 完成后再接入图片、文件和微信小程序。

第一版以稳定的文字问答、会话连续性和明确错误提示为目标，不同时扩展过多功能。
